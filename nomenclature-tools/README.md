# Инструменты номенклатуры

Расширение для 1С:Бухгалтерия предприятия 3.0, платформа 8.3.24+ (писалось под БП 3.0.194, платформа 8.3.27).
Инструменты в списке номенклатуры (и в окне выбора номенклатуры):

| Клавиши | Команда |
|---|---|
| `Ctrl+R` | [переименовать выделенные](#массовое-переименование) в текст из буфера обмена |
| `Ctrl+Z` | откатить последнее переименование |
| `Ctrl+D` | [добавить выделенные в очередь объединения](#очередь-объединения) — мгновенно |
| меню «Еще» | объединить очередь…, очистить очередь, объединить выделенные сейчас (форма БСП) |
| меню «Еще» | [найти двойников у минусов](#двойники-у-минусов) |
| меню «Еще» | [автообъединение дублей у минусов](#автообъединение-дублей-у-минусов) — только администратор |

Все команды есть и в меню **Еще**.

## Обычный порядок работы

1. В поле поиска списка ввести часть названия, найти карточки-дубли.
2. Выделить их (`Ctrl`+клик).
3. Скопировать правильное название → `Ctrl+R` — все выделенные получили это название (если нужно).
4. `Ctrl+D` — группа ушла в очередь, сразу искать следующую.
5. Набрав пар — **Еще → Объединить очередь…** → проверить список → «Да» → объединяется подряд без участия.

Что расширение может и чего не может — в [БЕЗОПАСНОСТЬ.md](БЕЗОПАСНОСТЬ.md).

## Массовое переименование

| Клавиши | Что делает |
|---|---|
| `Ctrl+R` | выделенные позиции номенклатуры получают **Наименование** и **Полное наименование** из буфера обмена |
| `Ctrl+Z` | откат последнего переименования — после вопроса «Откатить…?» (хранится до 20 операций, можно повторять) |

- Окна не открываются: результат показывается всплывающим оповещением в углу экрана.
- Клавиши работают и из поля поиска: берутся строки, выделенные в списке.
- Команды также есть в меню **Еще** списка номенклатуры.
- Работает в списке (Справочники → Номенклатура) и в окне выбора номенклатуры (например, из отчета).
- Доступно только пользователю `Стажер` (настройка `РазрешенныйПользователь()` в `МП_ПереименованиеВызовСервера`).

### Как пользоваться

1. Скопировать новое название (`Ctrl+C`). Через AnyDesk буфер синхронизируется — копировать можно и на своем ПК.
2. В списке номенклатуры выделить строки (`Ctrl`+клик или `Shift`+стрелки).
3. `Ctrl+R`. Ошиблись — `Ctrl+Z`.

Ничего не изменится, если: в буфере несколько строк или таблица; текст длиннее допустимого; хоть одна позиция
не записалась (все пишутся одной транзакцией). Группы пропускаются.

## Очередь объединения

Объединение одной группы занимает ~20 секунд (поиск мест использования по всей базе). Чтобы не ждать,
группы копятся в очереди, а объединяются потом подряд.

- `Ctrl+D` — выделенные карточки (минимум две, без групп) **мгновенно** добавляются в очередь одной группой.
  Если какая-то из них уже в очереди — группы склеиваются (можно добавить третий дубль позже).
- **Еще → Объединить очередь…** — список групп с флажками:
  ```
  ☑ сигареты бла 1шт (-3) + Сигареты бла (0)  →  СИГАРЕТЫ БЛА шт (+20)
  ☐ [есть в других фирмах] ESSE (-5)  →  ESSE BLACK GOLD (+12)
  ```
  Справа от `→` — **основная** карточка: с наибольшим остатком по организации из настроек,
  при равенстве — самая старая по коду. В нее сливаются **все** остальные карточки группы.
  Группы с проводками других фирм по умолчанию **не отмечены**.
- После вопроса «Объединить групп: N?» (по умолчанию «Нет») группы объединяются подряд штатной заменой ссылок
  БСП, лишние карточки помечаются на удаление. Объединенные уходят из очереди, неудачные остаются в ней,
  причины — в сообщениях.
- Очередь хранится в базе, в настройках пользователя: переживает перезапуск, видна из второго окна 1С
  под тем же пользователем. **Еще → Очистить очередь объединения** — убрать всё.
- Пока объединяется очередь, это окно 1С занято. Искать можно во втором окне 1С.

**Еще → Объединить выделенные сейчас (форма)** — старый вариант: штатная форма БСП «Объединение элементов»
для выделенных карточек, основную выбираете сами.

Доступно Стажеру и администраторам (объединение может потребовать прав администратора).

## Двойники у минусов

**Еще → Найти двойников у минусов** в списке номенклатуры. Доступно Стажеру и администраторам.

1. Ищутся карточки с **отрицательным количеством** по счету 41 (с субсчетами, текущие остатки)
   **по организации из настройки** (`АРАБИКА`), у которых есть другие карточки с таким же названием.
2. Названия сравниваются без учета регистра, кавычек, скобок, лишних пробелов, `ё`/`е` и хвоста
   `шт` / `1шт` / `1 шт.`: «Сигареты бла 1шт» и «СИГАРЕТЫ БЛА шт» — двойники.
   Другие числа перед «шт» остаются: «бла 2шт» и «бла 10 шт» — разные товары, в одну группу не попадут.
3. Открывается окно со списком групп:
   ```
   = ESSE BLACK GOLD (-5)  |  ESSE BLACK GOLD (+12)
   ≈ Сигареты бла 1шт (-3)  |  сигареты бла шт (+20)
   ```
   `=` — названия совпадают полностью, `≈` — совпадают после чистки (проверьте глазами).
   `[есть в других фирмах]` — у карточек группы есть проводки другой организации: объединение изменит
   и ее документы. Такие группы объединять только по согласованию.
   Сначала карточка с минусом, затем двойники; в скобках — количество.
4. Выбранная группа открывается в штатной форме БСП **«Объединение элементов»**:
   там выбирается основная карточка, видны места использования, объединение — только после подтверждения.
   Для следующей группы — запустить команду снова: объединенные группы из списка пропадут.

Сам поиск **ничего не меняет** в базе. Меняет данные только штатное объединение: ссылки на двойника
во **всех документах, в том числе прошлых периодов**, заменяются на основную карточку, двойник удаляется.
Это не откатывается через `Ctrl+Z` — только из резервной копии. Поэтому:
- что объединять, решает бухгалтер;
- объединение обычно требует прав администратора — открывать под администратором;
- перед объединением — свежая резервная копия.

## Автообъединение дублей у минусов

**Еще → Автообъединение дублей у минусов…** — команда видна **только администратору**.
Объединяет сразу много групп без формы БСП на каждую.

Какие группы попадают:
- группы двойников из поиска выше (и `=`, и `≈`), в которых есть карточка **с минусом** и карточка
  **с положительным остатком** (по организации из настройки);
- группы с пометкой `[есть в других фирмах]` **пропускаются**.

Что происходит с группой:
- **основная** — карточка с наибольшим остатком;
- в нее сливаются **только карточки с минусом**: ссылки на них во всех документах заменяются на основную,
  сами они **помечаются на удаление** (окончательно удаляет штатное «Удаление помеченных объектов»);
- карточки с нулем и вторые «плюсовые» не трогаются.

Как выглядит:
1. Окно-план со всеми группами, флажки отмечены: `сигареты бла 1шт (-3)  →  СИГАРЕТЫ БЛА шт (+20)`.
   Снимите флажки с групп, которые объединять не надо, → **ОК**.
2. Вопрос «Объединить групп: N? … Отменить можно только из резервной копии» (по умолчанию — «Нет»).
3. Группы объединяются по одной. Перед каждой условия перепроверяются по текущим остаткам: если что-то
   изменилось, группа пропускается. Итог — «Объединено групп: N из M», причины пропусков — в сообщениях.

Объединение выполняется штатной заменой ссылок БСП (`ОбщегоНазначения.ЗаменитьСсылки`) — тем же механизмом,
что у «Поиска и удаления дублей». **Перед запуском — свежая резервная копия и согласие бухгалтера.**
Первый запуск — на тестовых карточках.

Настройки в `МП_ДублиВызовСервера` (область `Настройки`):
- `ОрганизацияДляОстатков()` — часть наименования организации (по умолчанию `"АРАБИКА"`; пусто — все организации вместе);
- `КодыСчетовТоваров()` — по умолчанию `"41"`, можно `"41,10"`;
- `РазрешенныйПользователь()`.

**Справочник номенклатуры общий для всех организаций базы.** Переименование и объединение меняют карточку
сразу для всех фирм — в том числе в их документах и печатных формах. Ограничить это одной организацией нельзя.

# Установка

Устанавливает **администратор** (в Конфигураторе), пользуется **Стажер**. Займет 15–20 минут.

## 0. Подготовка

1. **Резервная копия базы** — обязательно (выгрузка `.dt` или бэкап SQL).
2. Если есть возможность — сначала поставить на **копию** базы и проверить там.
3. Открыть файлы с кодом в этом репозитории (понадобятся для копирования):
   - [src/CommonModules/МП_ПереименованиеВызовСервера.bsl](src/CommonModules/МП_ПереименованиеВызовСервера.bsl)
   - [src/CommonModules/МП_ПереименованиеКлиент.bsl](src/CommonModules/МП_ПереименованиеКлиент.bsl)
   - [src/CommonModules/МП_ДублиВызовСервера.bsl](src/CommonModules/МП_ДублиВызовСервера.bsl)
   - [src/CommonModules/МП_ДублиКлиент.bsl](src/CommonModules/МП_ДублиКлиент.bsl)
   - [src/Forms/МодульФормыНоменклатуры.bsl](src/Forms/МодульФормыНоменклатуры.bsl)

   На GitHub у файла есть кнопка **Copy raw file** — копирует весь текст.
4. *(Необязательно)* Ограничение по компьютеру: на рабочем ПК `Win+R` → `cmd` → `hostname`, запомнить имя.

## 1. Войти в Конфигуратор

1. Запустить 1С → выбрать базу → **Конфигуратор** → войти под **администратором**.
   - Нет кнопки «Конфигуратор» — установлен только тонкий клиент. Нужен дистрибутив платформы 8.3.27
     с компонентом «1С:Предприятие» (полная версия).
2. **Конфигурация → Открыть конфигурацию**.

## 2. Создать расширение

1. **Конфигурация → Расширения конфигурации** → кнопка **Добавить**.
2. Заполнить:
   - Имя: `ИнструментыНоменклатуры`
   - Синоним: `Инструменты номенклатуры`
   - Префикс: `МП_`
   - Назначение: `Дополнение`
3. В списке расширений у нового расширения флажок **Безопасный режим** — **оставить включенным**.
4. Выделить расширение → кнопка **Конфигурация → Открыть конфигурацию**.
   Откроется отдельное дерево расширения.

## 3. Заимствовать формы номенклатуры

В дереве **основной** конфигурации: **Справочники → Номенклатура → Формы**.
Правой кнопкой по форме → **Добавить в расширение** → `ИнструментыНоменклатуры`. Сделать для двух форм:
- `ФормаСписка`
- `ФормаВыбора`

## 4. Создать четыре общих модуля

В дереве **расширения**: **Общие → Общие модули** → правой кнопкой → **Добавить**.

**Модуль 1**
- Имя: `МП_ПереименованиеВызовСервера`
- В свойствах (`Alt+Enter`) флажки: ☑ **Сервер**, ☑ **Вызов сервера**, все остальные сняты.
- Открыть модуль, вставить весь текст `МП_ПереименованиеВызовСервера.bsl`.
- В начале модуля, в `РазрешенныйПользователь()`, — имя пользователя (сейчас `"Стажер"`).

**Модуль 2**
- Имя: `МП_ПереименованиеКлиент`
- Флажки: ☑ **Клиент (управляемое приложение)**, все остальные сняты (**Сервер** — снять!).
- Вставить весь текст `МП_ПереименованиеКлиент.bsl`.
- *(Необязательно)* в `РазрешенныйКомпьютер()` вписать имя ПК из шага 0.4.

**Модуль 3**
- Имя: `МП_ДублиВызовСервера`
- Флажки: ☑ **Сервер**, ☑ **Вызов сервера**, все остальные сняты.
- Вставить весь текст `МП_ДублиВызовСервера.bsl`.

**Модуль 4**
- Имя: `МП_ДублиКлиент`
- Флажки: ☑ **Клиент (управляемое приложение)**, все остальные сняты.
- Вставить весь текст `МП_ДублиКлиент.bsl`.

## 5. Настроить формы (для `ФормаСписка`, потом то же для `ФормаВыбора`)

1. В дереве **расширения**: **Справочники → Номенклатура → Формы → ФормаСписка** — двойной клик, откроется редактор формы.
2. Подключить обработчик:
   - в дереве элементов (слева вверху) выделить самый верхний узел **Форма**, открыть свойства (`Alt+Enter`);
   - раздел **События** → строка **ПриСозданииНаСервере** → кнопка добавления обработчика расширения →
     тип вызова **«После»**;
   - Конфигуратор создаст в модуле процедуру `МП_ПриСозданииНаСервереПосле`.
3. Вкладка **Модуль** (внизу редактора) → выделить всё (`Ctrl+A`) → вставить весь текст `МодульФормыНоменклатуры.bsl`.
4. Проверить: в свойствах формы у события **ПриСозданииНаСервере** указан обработчик
   `МП_ПриСозданииНаСервереПосле` с вызовом «После». Если Конфигуратор назвал процедуру по-другому —
   переименовать ее в модуле в `МП_ПриСозданииНаСервереПосле` и выбрать в свойствах заново.

## 6. Проверить и применить

1. В окне расширения: **Конфигурация → Проверка конфигурации** → ошибок быть не должно.
   Если есть — прислать скриншот, ничего не применять.
2. **Конфигурация → Обновить конфигурацию базы данных** (`F7`). Монопольный режим не нужен,
   пользователей выгонять не нужно.
3. Закрыть Конфигуратор.

## 7. Проверить под Стажером

1. Запустить 1С:Предприятие под **Стажером** (уже открытые сеансы увидят расширение только после перезапуска).
2. **Справочники → Номенклатура** → меню **Еще** → должны быть команды «Переименовать в текст из буфера обмена»,
   «Откатить последнее переименование», «Объединить выделенные» и «Найти двойников у минусов».
3. Создать две тестовые позиции, например `ТЕСТ 1` и `ТЕСТ 2`.
4. Скопировать текст `ТЕСТ ПЕРЕИМЕНОВАН`, выделить обе позиции, нажать `Ctrl+R` → обе переименованы
   (открыть карточку: «Полное наименование» тоже поменялось).
5. `Ctrl+Z` → вопрос «Откатить переименование 2 поз.…?» → «Да» → снова `ТЕСТ 1` и `ТЕСТ 2`.
6. Выделить обе тестовые позиции → `Ctrl+D` → «В очереди: 1 гр.» → **Еще → Объединить очередь…** →
   в списке одна группа → ОК → «Да» → «Объединено групп: 1 из 1», одна из тестовых помечена на удаление.
7. **Еще → Найти двойников у минусов** → открывается окно со списком (или «Двойников у минусов не найдено»).
   Сверить пару строк с отчетом по отрицательным остаткам. **Ничего не выбирать, закрыть окно** —
   объединение пробовать только с бухгалтером.
8. Под администратором открыть номенклатуру — в «Еще» должны быть только «Объединить выделенные»,
   «Найти двойников у минусов» и «Автообъединение дублей у минусов…».
   Автообъединение проверять на тестовых карточках: `ТЕСТ ДУБЛЬ` с минусом и `ТЕСТ ДУБЛЬ` с плюсом
   (например, оприходовать 1 шт и продать 1 шт с другой карточки) — после бэкапа и с бухгалтером.
9. Удалить оставшиеся тестовые позиции (пометить на удаление).

## 8. Сохранить расширение в репозиторий

В окне расширения: **Конфигурация → Выгрузить конфигурацию в файлы** → папка `nomenclature-tools/xml` репозитория →
закоммитить и запушить. Дальше правки можно делать в файлах.

## Если не работает

| Что видно | Причина и что делать |
|---|---|
| Команд нет в меню «Еще» | Не совпало имя пользователя в `РазрешенныйПользователь()`, или не подключен обработчик из шага 5.2. Ошибки при добавлении команд пишутся в **журнал регистрации** (Администрирование → Обслуживание → Журнал регистрации), события `МП_МассовоеПереименование` и `МП_ПоискДвойников`. |
| Хоткей ничего не делает через AnyDesk, а команда в «Еще» работает | AnyDesk в режиме перевода символов искажает сочетания с `Shift`. Поэтому хоткеи — `Ctrl+буква` без `Shift`. Если и они не доходят — переключить клавиатуру AnyDesk в режим 1:1. |
| Хоткей ничего не делает, а команда в «Еще» работает (не AnyDesk) | Сочетание занято платформой или БП. Поменять букву в `ДобавитьКоманды` (`Клавиша.R` и т.п.) и обновить конфигурацию БД. |
| «Недостаточно прав» при `Ctrl+R`, хотя вручную переименовать позицию получается | В безопасном режиме стандартный код БП не может включить привилегированный режим. Снять флажок **Безопасный режим** у расширения (Конфигуратор → Расширения конфигурации) и обновить конфигурацию БД (`F7`). |
| Ошибка проверки про `СредстваБуфераОбмена` | Режим совместимости ниже 8.3.24 — прислать скриншот, сделаю вариант без него. |
| «Не выделено ни одной позиции» | В списке ничего не выделено или открыт не список номенклатуры. |
| Очередь: группы не объединяются, в сообщениях ошибка прав | Нет прав на объединение — запускать «Объединить очередь» под администратором (очередь у каждого пользователя своя: набирать тоже под ним). |
| Двойники: «В плане счетов не найдены счета» | Поправить `КодыСчетовТоваров()` в `МП_ДублиВызовСервера`. |
| Двойники: «Не найдена организация» / «подходят несколько организаций» | Поправить `ОрганизацияДляОстатков()`: часть названия, как в Справочники → Организации. |
| Двойники: после отметки ничего не открывается | Нет прав на объединение — запускать под администратором. |
| Двойники: в окне нет пары, которая точно есть | Названия отличаются не только регистром/кавычками/«шт» (например, «Ессе» и «ESSE»). Такие пары ищет штатный **Администрирование → Обслуживание → Поиск и удаление дублей**, режим «похожие слова». |

## Как удалить

**Администрирование → Печатные формы, отчеты и обработки → Расширения** (или Конфигуратор →
Расширения конфигурации) → снять «Активно» или удалить. После перезапуска 1С всё как до установки.
Уже сделанные переименования останутся — при необходимости откатить их `Ctrl+Z` до удаления.
